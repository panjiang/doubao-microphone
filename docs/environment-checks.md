# 配置页运行环境检测

Windows 配置页“1 · 检查电脑”打开后自动检测，也可点击“重新检测”。五项分别展示虚拟麦克风、豆包安装及运行、豆包麦克风配置、当前触发配置、语音快捷键开关。检测期间左侧为 loading 动画，结果为绿色勾、红色叉、黄色问号或灰色减号，并提供状态文字和原因。

检测读取程序当前已保存的配置、豆包当前用户配置文件、启用的音频端点、安装记录、程序文件和进程信息。它不保存豆包配置、不发送按键、不启动豆包、不创建录音流、不自动更改系统默认设备。

## 判定边界

- 不使用豆包版本号或 schemaVersion 作为准入条件；按字段类型、已确认的快捷键编码和实际设备进行匹配。
- 虚拟麦克风必须同时存在启用的 CABLE Input、CABLE Output，程序输出也必须能唯一解析到 CABLE Input。
- 豆包保存的麦克风 ID 与录音端点原始 ID／完整 ID 精确比较。跟随默认设备、未知字段或读取失败显示“无法确认”，不据此猜测正确。
- 已确认的右 Alt 编码与配置匹配才通过；能明确判定额外按键或空快捷键时提示不一致；其他未识别编码显示无法确认。UMDF 方式额外只打开、关闭组件控制接口检查访问权限，不发送 feature report。
- 工具栏方式检查已保存的工具栏开关，语音快捷键开关显示“不适用”。这不证明工具栏点击、ASR、焦点或实际文字输入已经验证。
- 各项分别处理读取错误，不因音频设备查询失败而丢失豆包安装检测结果。模拟模式不检查实际环境；macOS 保留原说明。

## 接口及前端行为

`GET /api/environment` 仅在本机管理路由开放，沿用 Host、Origin 和 Bearer 令牌校验。返回 `supported` 与 `checks`；每项包含稳定的 `id`、`title`、`state`、`detail`。状态为 `pass`、`fail`、`unknown`、`not_applicable`。

原生检查在 Tokio 阻塞工作线程执行，同一进程最多一个检测任务。前端不读取或改写设置表单；十秒超时会中止请求、结束 loading 并显示无法确认，随后允许重试。检测按钮位于设置表单外，不触发表单保存或快捷键测试。

## 待用户实测的人工验收

本次只完成构建和源代码检查，未执行以下交互验证：

1. 安装新版、退出旧程序后重新打开配置页，观察 loading 到各项结果的变化。
2. 在表单中修改电脑名称但不保存，点击“重新检测”，确认未保存内容保留，检查仍依据已保存配置。
3. 手动更改豆包麦克风或关闭语音快捷键后重新检测，确认提示原因；恢复正确配置并再检查。
4. 手动选择工具栏触发并保存，确认检查项改为工具栏配置，快捷键开关显示不适用。
5. 确认未识别字段、访问失败和请求失败时显示无法确认；服务不可达或请求超过十秒时不持续转圈，可再次点击检测。

不得为验收而未经用户操作自动启用麦克风、触发快捷键，或破坏当前可用的驱动及豆包配置。
