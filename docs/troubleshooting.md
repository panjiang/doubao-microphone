# 故障排查与卸载

首次使用请先完成[安装与配置](getting-started.md)。配置页的环境检查是只读检测，全部通过也不能替代实际语音输入验证。

## App 显示“已配对”，但没有连接

“已配对”表示手机保存了电脑凭据。实时连接在按住说话时建立，不会一直保持或在后台自动重连。第一次使用请允许麦克风与局域网访问；若授权期间已松手，完成授权后重新按住。

## 无法扫码或二维码失效

统一二维码需要桌面端 0.2.2 和 App 0.1.0 构建 23。更早的 App 只识别旧 JSON 格式，需先更新；新版 App 仍能识别旧桌面的 JSON 码。

二维码五分钟内单次有效，重新生成会使旧码失效。用 App 或手机相机任一入口成功配对后，该码不能再给另一入口使用；需要时在电脑重新生成。

## 手机连不上电脑或打不开网页

- 核对电脑配置页选中的局域网 IP。电脑可以接网线，手机需位于可互相访问的 Wi-Fi 网络。
- 排除访客网络隔离、VPN 和虚拟网卡导致的地址选择问题。
- 按系统提示允许本程序的私人网络入站连接。默认手机端口为 `38441` 和 `38443`。
- 管理页 `127.0.0.1:38440` 只属于电脑本机，不能把它当作手机地址。

IP 或端口改变后，退出并重开电脑程序，再重新扫码。App 握手失败或超时会显示错误；恢复网络后重新按住，不会重播上一次录音。

## Safari 麦克风权限或证书错误

此项针对**手机网页**；App 不需要安装系统根证书。

Safari 必须使用 HTTPS 输入页。下载并安装描述文件后，还要在 iPhone「设置 → 通用 → 关于本机 → 证书信任设置」开启本机 CA 的完全信任。HTTP 页面只用于首次配置，不能采音。

返回向导完成信任；二维码过期则重新生成。原 CA 未改变时不必重复信任，但地址变化后 Safari 可能再次请求麦克风权限。

## 手机有音量，电脑没有文字

先核对音频路由：Windows 程序输出到 **CABLE Input**，豆包选择 **CABLE Output**；Mac 两端都选择 **BlackHole 2ch**。请在豆包中明确选择设备，避免依赖自动或默认设备碰巧正确。

然后在目标输入框使用实体快捷键，确认豆包本身可以启动并输入。若实体键也没有效果，应先处理豆包设置或权限；若实体键有效、手机触发无效，再检查下列触发条件。程序的 complete 回执只代表本次声音和按键流程结束，不是豆包识别结果。

## 快捷键拒绝或没有效果

- 松开电脑上的 Alt、Control、Command、Shift 等实体修饰键。
- Windows 的右 Alt 自动方式依赖可访问的 UMDF 组件；普通安装器不包含该研究组件。未安装时的工具栏兼容模式仅适配默认安装位置的豆包 1.0.0.23，并要求开启悬浮工具栏。
- Windows 首版不支持向管理员权限应用输入，请先在普通权限编辑器中确认。
- Mac 允许主应用和包内输入代理的辅助功能权限，并确认豆包长按键与 Fn 设置一致。当前未使用豆包时，还需检查是否启用了豆包全局语音。

权限或代理出错时查看配置页的具体原因。快捷键测试会真实影响前台应用，应先切到专用测试文档。

### 没有手动暂停，却提示“电脑已暂停接收”

新版将三类情况分开处理：

- **已手动暂停**：只有托盘或配置页的暂停操作设置该状态，需由用户恢复；后台恢复不会改变它。
- **连接断开或音频异常**：结束当前会话，取消待发 Enter，释放快捷键并清空声音；下次按住重新连接和打开音频设备，不设置全局暂停。
- **输入服务恢复中**：输入代理异常后，先确认旧进程退出及按键释放，再重建代理并做不触发按键的通信握手。最多连续尝试三次，等待约 0.5、1、2 秒；持续健康运行 30 秒后恢复重试额度。重建失败或短时间反复崩溃耗尽额度后显示“输入服务需处理”，请检查权限或重启电脑程序。

断网、切换 Wi-Fi、锁屏或电脑休眠均会结束本次输入；恢复后需重新按住，不续播旧录音、不重新按下旧快捷键、不补发旧 Enter。电脑 IP 改变仍需更新电脑地址并重新扫码；配对撤销也需要重新配对。

同一已配对手机重新连接时会清理并替换自己的旧连接，旧连接的结束、断开和音频消息不能作用于新会话；另一部手机不能抢占仍有效的连接。手机网页也会在电脑超过一秒无响应时主动断开，下一次按住建立新连接。

早期版本在输入代理响应超时后仍复用旧通道，迟到回复可能被后续 Enter 命令读到，出现“输入代理未返回 Enter 结果”并触发暂停。修复后内部请求与回复按编号对应，通信超时或协议错误不再复用旧通道；旧代理未确认退出或按键释放未确认时，不创建替代代理。

实机验收时分别确认：录音中断网、等待 Enter 时断网、切后台/锁屏、电脑休眠唤醒、代理异常退出后下一次按住可重新开始；另确认手动暂停在故障恢复后仍保持、旧连接不能影响新会话。构建通过不代表这些故障场景已经全部实测。

## 回车没有发出，或发得太早

正常完成并释放语音快捷键后，才开始计算回车等待。以下情况会取消或跳过 Enter：再次按住、断线、暂停、修改设置、退出、原目标窗口或控件变化、实体修饰键仍按住，以及本次输入未正常完成。

固定等待不保证豆包已写完文字。如果回车过早，可在配置页增加等待值。同一浏览器原生窗口中的 DOM 输入框切换可能无法由 Windows 的窗口句柄区分，等待时请保持目标输入框。

## 听写截断或延迟

先在稳定的局域网环境中复测。队列超过上限会结束本次输入，不会无限积压后重放旧声音。启动等待默认 350ms，可设为 100–450ms；不要通过无限等待掩盖触发失败。

切后台、锁屏、来电、设备变化或网络中断会结束当前会话。等本次结束后重新按住；结束后的新按住会取消待发 Enter。

### 只识别开头，或豆包中途停止

可在配置页手动开启「故障录音诊断」，再复现一次。样本位于本机数据目录的 `diagnostics/`，包含手机音频、成功采集时的虚拟麦克风回读以及 `report.json` 状态时间线。每份最多 30 秒，保留最近 3 次正常和 3 次故障样本；缺少回读文件表示采集失败，不能据此认定音频完整。

诊断默认关闭，不上传文件；关闭后停止新采集，已有文件可手动删除。反馈问题时先提供系统、豆包版本、入口及错误提示，不需要公开录音、二维码或带令牌的管理 URL。

### Codex 空输入框首次语音失败

Windows 工具栏兼容模式提供默认关闭的「Codex 空框兼容（先补一个空格）」。开启后，仅在受支持的 Codex 空白编辑器中先插入一个普通空格再启动语音；已有内容和其他程序不处理。

该选项会读取必要的空白状态来判断目标，不保存正文；它属于特定应用间的兼容处理，不是通用语音触发方式。可在配置页关闭，研究依据见 [Windows 兼容性记录](windows-input-findings.md)。

## 登录自启动

安装默认启用，可在配置页关闭；Mac 升级保留已保存的选择。启动后只在后台提供托盘或菜单栏，不自动打开配置页。

Windows 使用当前用户的 Run 启动项；Mac 使用 `~/Library/LaunchAgents/local.doubao-remote.plist`，在登录时运行，不安装系统服务。开发环境使用自定义数据目录时，不建议启用登录启动。

## 卸载

先在配置页关闭登录自启动，并从托盘或菜单栏退出。

- **Windows 安装版**：通过系统卸载，安装器移除本软件程序、配置和启动项。便携版需自行删除应用及对应数据目录。
- **macOS**：删除应用和本软件 LaunchAgent；需要清除配对及证书时，删除 `~/Library/Application Support/local.DoubaoRemote.DoubaoRemote`，覆盖升级可能继续使用原数据目录；以配置页诊断中显示的实际位置为准。在「钥匙串访问」移除该电脑对应的 `local.doubao-remote` CA 项，旧安装可能保留兼容名称。系统中的辅助功能授权可同时撤销。
- **iPhone App**：可先在电脑配置页撤销该设备凭据，再删除 App。
- **iPhone 网页**：移除主屏幕网页及站点数据；如安装过本机证书描述文件，在「设置 → 通用 → VPN 与设备管理」手动移除。

虚拟音频设备可能被其他应用共用，因此不自动卸载 VB-CABLE 或 BlackHole。额外安装的研究键盘组件应按其独立说明移除。
