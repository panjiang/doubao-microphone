# 配置与故障排查

## 手机上无法打开网页

核对电脑配置页的局域网 IPv4，手机与电脑处于同一路由器且不是隔离的访客网络。只放行程序使用的私人网络入站端口。管理页面只在电脑回环地址提供，不能把电脑的 `127.0.0.1` URL 发给手机。

IP 或端口变更需重启、重新扫码。原 CA 没有改变时不需要重新信任证书，但 Safari 对新地址可能再次请求麦克风权限。

## 麦克风权限不可用／证书错误

必须使用 HTTPS 输入页；证书安装之后还必须在 iPhone 的“证书信任设置”开启完全信任。HTTP 证书向导没有麦克风功能。不要绕过证书警告后期待采集可用；回到向导完成信任。二维码过期后在电脑生成新的二维码。

## 手机有音量，豆包没有文字

先检查实际音频路由。Windows 本程序向 CABLE Input 播放，豆包从 CABLE Output 录制；macOS 使用 BlackHole 2ch 的输出和输入两端。不要选扬声器、手机本身的麦克风或系统默认输出进行猜测。

先做物理快捷键测试，再做模拟快捷键测试，最后做 WAV 输入测试。程序只知道自己提交了按键和音频，无法验证豆包实际识别结果。错误 code 和 complete 不是识别成功证据。

## 快捷键拒绝或没有效果

先松开电脑上的 Alt／Control／Command／Shift 等实体修饰键。Windows 确认目标应用没有以管理员身份运行；macOS 检查主应用与输入代理的辅助功能权限。当前版本豆包是否接受模拟 Fn 必须实测；不提供私有输入注入方案。

代理错误后程序会暂停，修复权限后退出重启。不要在未查明原因时反复触发测试键。

## 听写截断或延迟

先在稳定 Wi-Fi 和近距离路由器条件下测试。网络队列超过上限主动中止，不回放旧语音。启动等待初值 350ms，只有实测豆包启动更快时才调低；若需超过 450ms 才能启动，记录兼容性问题，不通过无限缓冲掩盖。

短按在准备阶段直接取消；松开后等待“本次声音已传完”，不要在 Draining 阶段重新开始。来电、锁屏、页面切后台会中断麦克风，需要重新连接。

## 登录自启动

默认关闭。Windows 写入当前用户的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\DoubaoPTT`；macOS 使用当前用户 `~/Library/LaunchAgents/local.doubao-ptt.plist`，只在下次登录运行，不安装系统服务。开发时自定义 `--data-dir` 不应启用登录自启动。

## 卸载

先在配置页关闭登录自启动，然后从托盘退出。

- Windows 安装版：使用系统卸载。便携版：删除应用，按启动日志中实际显示的路径删除本软件数据目录；如曾手动添加防火墙规则，移除名为 DoubaoPTT LAN 的规则。
- macOS：删除应用和 `~/Library/LaunchAgents/local.doubao-ptt.plist`，按启动日志中实际路径删除应用数据目录。在“钥匙串访问”删除 service 为 `local.doubao-ptt` 的本软件 CA 凭据；名称按当前数据目录哈希区分。撤销主应用与输入代理辅助功能授权。
- iPhone：设置 → 通用 → VPN 与设备管理，删除“豆包语音遥控 · 本机证书”描述文件；删除主屏幕网页及该站点数据。

不自动卸载 VB-CABLE／BlackHole，也不修改其他应用的音频配置。

## 只识别第一个字或豆包面板中途消失

0.1.2 检测豆包录音提前结束并停止本次发送，提示 `doubao_stopped`。它修复会话仍误显示 streaming 的问题，不能据此认定豆包退出原因已解决。可在配置页启用「故障录音诊断」，使用后复现即可，正常和故障样本分开轮换。Windows 默认目录为 `%LOCALAPPDATA%\DoubaoPTT\DoubaoPTT\data\diagnostics`。对比 `phone.wav` 与 `virtual-microphone.wav`，并核对 `report.json` 中音量和 recording/panel_visible 时间线，区分手机声源、虚拟设备和豆包录音中断。报告明确记录丢帧、采集失败；没有回读文件时不能声称虚拟麦克风声音完整。录音仅本机保存，关闭开关停止新采集，删除 diagnostics 文件夹清除已有样本。
