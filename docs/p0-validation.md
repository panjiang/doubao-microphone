# P0 实机验证步骤

此文件是执行步骤，不是已经通过的测试报告。实际结论填写到 verification.md，保留系统版本、架构、豆包版本和虚拟设备版本。

## Windows

1. 安装官方 VB-CABLE，按其提示重启；`probe devices` 应显示 CABLE Input。
2. 豆包输入来源选择 CABLE Output。确认物理按住左 Alt 可以在记事本中语音输入。
3. 执行 `probe key --key left_alt --seconds 3`，倒计时后观察豆包语音面板启动与结束。只确认面板行为，不凭 SendInput 返回值判成功。
4. 准备含清楚中文语音的 16-bit PCM WAV，执行 `probe audio --wav sample.wav --device "设备完整名称或ID" --hold-key left_alt`，确认文字落入原输入框，首字和尾字完整。
5. 启动托盘程序，按向导连接 iPhone。保持屏幕亮起，至少完成一句完整口述。
6. 用记事本、浏览器、日常编辑器分别重复，测试 44100／48000Hz 手机采样率、快速短按、取消、连续操作。

原生按键测试会影响当前前台应用，测试前先选择专用输入框。首版不支持管理员权限应用、锁屏桌面或 UAC 安全桌面。

## macOS

1. 用 Mac 构建对应架构 `.app`，安装 BlackHole 2ch，设置豆包输入设备。
2. 授权主应用和包内的 DoubaoRemoteInput.app 输入代理辅助功能权限。
3. 先确认物理 Fn 在当前豆包版本上有效，再执行 `probe key --key fn --seconds 3`。
4. 如模拟 Fn 被拒绝，查明豆包是否允许改绑其他长按快捷键；仅在允许时改绑并同步本机配置。若无可用键，记录阻塞，不绕过系统限制。
5. 重复 WAV、iPhone、不同输入框和异常测试。分别记录 Apple Silicon 与 Intel 实机结果，未测试架构不标通过。

## 异常与耐久

- 按住时断 Wi-Fi、锁屏、切后台、切出 Safari、触摸取消、接听电话。
- 按住时结束主进程，检查输入代理最多在租约到期后释放快捷键；单独结束代理，检查主进程释放并暂停。
- 虚拟音频设备不可用、权限撤销、电脑休眠与唤醒，不能继续旧会话。
- 实体修饰键冲突时拒绝远程开始；必须实际观察，没有错误释放人的实体按键。
- 连续 30 分钟、至少 100 次操作，检查无卡键、会话重放或延迟持续增长。
- 用单调时间测量至少 100 次开始／结束。P95 就绪目标 ≤600ms，正常结束目标 ≤800ms；不含豆包识别后处理。记录原始统计，不凭主观感觉填写。

任一关键环节失败时，说明具体失败条件、日志代码和复现步骤，保留 P0 未通过状态。
