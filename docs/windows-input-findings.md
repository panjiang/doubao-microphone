# Windows 豆包快捷键兼容性：结论与经验

日期：2026-11-03。范围：本机 Windows 11、豆包输入法 **1.0.0.23**、UMDF 研究版 **0.1.5-umdf.1**。逐项实测和发布缺口见 [UMDF 验证记录](../research/windows-umdf/VALIDATION.md)。

## 豆包跳过什么，没有跳过什么

在已检查的版本中，豆包键盘钩子的语音快捷键处理会检查 **`LLKHF_INJECTED`（0x10）**；带该标记的事件跳过语音处理，并继续调用 `CallNextHookEx`。这不是 Windows 全局禁止模拟键盘，也不是豆包把该事件从系统中删除。其他窗口仍可能收到事件，例如激活菜单。

| 输入路径 | 已观察到的标记 | 本轮豆包表现 |
| --- | --- | --- |
| `SendInput` 模拟右 Alt／右 Ctrl | `injected=1` | 未唤起语音；继续改扫描码不解决该过滤条件 |
| 实体右 Alt | 本轮实体对照以用户操作和反馈为准，未取得独立可靠的标记基线 | 用户确认可在记事本唤起语音 |
| 本项目 UMDF HID 右 Alt | 对应按下及释放 `injected=0` | 在正确快捷键和记事本输入焦点下，用户确认唤起并正常结束；手机完整链路也确认能输入文字 |

微软对该位的定义是“事件是否被注入”，不是“是否由真人操作”。**`injected=0` 不证明实体键盘或真人输入。** Windows 仍知道 UMDF 设备是虚拟设备；该版本豆包的这个过滤条件没有据此拒绝本轮事件，不代表其他应用或未来版本必然接受。[KBDLLHOOKSTRUCT 官方定义](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-kbdllhookstruct)

静态检查定位到 `ImeService.exe` 的 `0x1407dec11: test al,0x10`、`injected` 分支字符串，以及跳转至 `0x1407df195` 的 `CallNextHookEx` 路径。地址仅属于所检查版本，不能用于其他构建。没有修改豆包文件、注入其进程或移除 Windows 事件标记。

## 为什么 UMDF 路线有效

旧路线是程序调用 `SendInput`，由系统生成带软件注入标记的键盘事件。新路线是本机输入代理向 UMDF HID 组件提交受限的键盘报告，再经过 Windows 自带的 HID／键盘栈形成事件；本轮对应事件没有该标记，因而没有命中上述过滤条件。不是修改系统开关把 `SendInput` 伪装成实体键盘。

UMDF 是用户态驱动路线，不等于无驱动。本机测试安装了组件，并将本研究代码签名证书加入本机信任；Secure Boot 保持开启、TESTSIGNING 保持关闭，没有修改 BIOS。自研 VHF 内核驱动遇到的加载与签名约束，不能直接推导为所有虚拟键盘方案都必须关闭 Secure Boot。[微软 UMDF HID 架构](https://learn.microsoft.com/en-us/windows-hardware/drivers/wdf/creating-umdf-hid-minidrivers)

## 排查时应保留的经验

1. **先核对当前实际快捷键和实体键对照。** 旧配置曾是右 Ctrl，当前豆包配置是右 Alt；错误键值的成功事件不能证明兼容。
2. **统一输入焦点再比较。** 初次 UMDF 右 Alt 未出现面板；明确让用户切回记事本输入区后成功。不能仅凭首次失败断言设备路径被拒绝，也不能断言焦点是当时唯一原因。
3. **菜单被激活不等于按成左 Alt。** 应同时检查 VK、扫描码、extended、按下／释放及 injected。旧模拟事件已经确认是右 Alt，菜单表现本身不能定位左右键错误。
4. **区分事件证据和产品证据。** `injected=0`、编译成功、设备启动都不足以证明豆包可用；还需用户确认唤起、输入和结束。本轮完整手机流程已有该反馈。
5. **不把局部钩子内存修改当成系统标记修改。** 两个独立进程的实验表明，发送侧修改回调结构体，没有改变接收侧观察到的注入标记。
6. **如实保留异常事件。** UMDF 右 Alt 自身的按下及释放为 0，但随后出现来源未归属的额外 `injected=1` 释放；不能把整段日志概括为全部无注入。

## 当前结论与未完成项

已打通本机手机按住 → UMDF 右 Alt → 豆包识别输入 → 松开结束，并验证一次不续租的超时释放。该结果支持继续开发 UMDF 路线。

它还不是正式发布验收：研究证书仅 14 天，普通权限、安装卸载、宿主及代理故障、电源变化、物理同键冲突、100 次／30 分钟耐久仍有缺口。UMDF 不适用于 macOS。后续工作以 [验证记录的剩余清单](../research/windows-umdf/VALIDATION.md#正式交付前的剩余工作) 为准，不重复把正常流程成功扩写成全部故障场景通过。
